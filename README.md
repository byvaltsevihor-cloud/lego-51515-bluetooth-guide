# Керування хабом LEGO 51515 з Mac

Працює через Bluetooth, без кабелю й без офіційного застосунку LEGO.

Якщо SPIKE Legacy після оновлення постійно показує «Update Hub»: [SPIKE-LEGACY-FIX.md](SPIKE-LEGACY-FIX.md).

Проблеми з підключенням до SPIKE Legacy і Robot Inventor: [TROUBLESHOOTING.md](TROUBLESHOOTING.md).

## Команди

Перед запуском увімкніть хаб коротким натисканням центральної кнопки. Кнопка Bluetooth не потрібна.

| Команда | Що робить |
| --- | --- |
| `./hub status` | стан хаба, портів і батареї |
| `./hub hello` | усмішка на екрані й два сигнали |
| `./hub watch --seconds 20` | сенсори, кнопки й нахил наживо |
| `./hub motortest` | кожен мотор на 30° туди й назад |
| `./hub motor A 90 25` | мотор A на 90° зі швидкістю 25% |
| `./hub stop` | зупинити всі мотори |
| `./hub exec "print(1 + 1)"` | виконати Python-код на хабі |
| `./hub run program.py` | запустити локальний файл на хабі |
| `./hub repl` | консоль хаба (вихід: Ctrl-]) |
| `./hub backup` | скопіювати програми з хаба в папку `backup/` |
| `./hub inforeply` | перевірити відповідь хаба на запит застосунку про версію |
| `./hub pad` | керувати Blast із контролера PlayStation 5: лівий стік ходьба, правий руки, R1/L1 мотор B, △/✕ швидкість, ○ стоп, Options вихід. `--check` перевіряє лише контролер |
| `./hub drive` | керувати Blast із клавіатури: стрілки, `w`/`s` руки, `x`/`z` мотор B, `+`/`-` швидкість, пробіл стоп, `q` вихід |

Команда стартує за 10–20 секунд: так закладено навмисно, див. «Правила зв'язку».

Напрямок мотора задає знак градусів у командах `./hub`. У самому API хаба `run_for_degrees`
ігнорує знак градусів, а напрямок задає знак швидкості.

## Встановлення

```sh
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
```

## Правила зв'язку

Двічі хаб вимкнувся приблизно за секунду після повторного підключення. Попередній сеанс тоді
закрився під час потоку телеметрії, а новий почався через 1–2 секунди. Найімовірніша причина
(аналіз прошивки, не доведено): збій прошивки при повторному відкритті каналу, а скидання на
батареї виглядає як вимкнення. Менш імовірні причини: пакет `Ctrl-C Ctrl-C Ctrl-B` або просідання
живлення. `hubctl.py` уникає цих умов:

- робочий runtime переривається лише одним `Ctrl-C` і лише через 7,5 секунди після підключення;
- між сеансами витримується щонайменше 12 секунд;
- сеанс не закривається під час телеметрії: спочатку `Ctrl-C`, а наприкінці `Ctrl-D`,
  який повертає стандартну роботу хаба;
- на одну команду одна спроба підключення, без повторних викликів.

Кожен сеанс пише сирий журнал у `logs/`, зберігаються останні 50. Якщо хаб знову вимкнеться,
зверніть увагу, чи згас він миттєво, чи після приблизно 2 секунд миготіння, і подивіться останній журнал.

## Чого не робити

- Не погоджуватися на оновлення хаба в SPIKE: Hub OS 3 не має Classic Bluetooth, тож `./hub`
  перестане працювати, а повернутися можна лише через USB.
- Не запускати два клієнти одночасно: `./hub`, SPIKE, застосунок на планшеті й Chrome ділять один канал.
  Закритого вікна SPIKE Legacy замало, потрібен Cmd-Q. `./hub` відмовиться працювати, поки застосунок запущений на цьому Mac.
- Не видаляти застосунок MINDSTORMS із планшета: в App Store його вже немає, тож повернути його може не вийти.
- Не використовувати Reset Settings і запуск із затиснутими лівою та правою кнопками:
  це може видалити збережені програми.
- Не натискати кнопку Bluetooth без потреби. За кодом прошивки вона відкриває вікно на 120 секунд,
  після якого хаб може вимкнутися.
- Не утримувати центральну кнопку після ввімкнення: за кодом прошивки приблизно 4 секунди утримання вимикають хаб.

## Що відомо про хаб

3 листопада 2026 року хаб оновлено через SPIKE Legacy 2.0.10 по Bluetooth, без кабелю. Застосунок показав
помилку, але прошивка встановилась, а 8 програм залишилися на хабі. Їхня копія лежить у `backup/`.

Після цього SPIKE Legacy знову вимагав оновлення. Причина: хаб не надсилає символ кінця повідомлення,
якщо відповідь довша за 1022 символи, а відповідь `get_hub_info` мала 1023. Тому файл `.extra_files_hash`
скорочено з 86 до 30 записів (`fix_extra_files_hash.py`), і відповідь тепер має 519 символів. Оригінал файлу
лежить у `backup/hub-root-20261103/`. Самі звукові файли на хабі не змінювалися. Якщо повертатися на прошивку
MINDSTORMS, файл варто відновити.

Прочитано з самого хаба:

- Зараз: прошивка v1.3.00.0000-e8c274a, MicroPython v1.14-876-gfbecba865 (2021-05-04), runtime 4.0.0-gecko.7.
- До оновлення: MicroPython v1.14-36-g377ea11 (2022-11-01), runtime 3.2.36. Значення таймерів і
  аналіз вимкнень нижче й вище стосуються цієї старої прошивки.
- Апаратна версія Version_E.
- Порти: A–D середні мотори (тип 75), E датчик відстані (62), F датчик кольору (61).
- Bluetooth Classic: Serial Port на RFCOMM-каналі 1, iAP2 на каналі 2.
- `INACTIVE_SHUTDOWN_MS` = 5 хв, `INACTIVE_SHUTDOWN_BT_MS` = 20 хв, `LONG_PRESS_MS` = 3 с.
  За кодом runtime хаб вимикається через 5 хвилин без відкритого каналу й через 20 хвилин із ним.
  Зарядний пристрій блокує цей таймер. Без runtime, у режимі консолі, власний таймер прошивки
  може спрацювати через 5 хвилин тиші (не перевірено).

Ролі моторів Blast, виведені з програм на хабі:

- A і C: ходьба (`move_pair C A`). `motortest` дає тут до 11° похибки й пише «ПЕРЕВІРИТИ»: ймовірно, через вагу робота на цих моторах.
- D: руки (програма «З руками і напоготові!»).
- B: ймовірно, стрільба або удар (програми «Навчальна стрільба», «Ураганний удар»).

На цьому macOS порт `/dev/cu.LEGOHub...` відкривається, але не передає жодного байта.
Тому `hubctl.py` працює з каналом RFCOMM напряму через IOBluetooth.
