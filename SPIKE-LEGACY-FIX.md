# SPIKE Legacy і хаб 51515: помилка оновлення та нескінченне «Update Hub»

Цей документ пояснює, що сталося з хабом LEGO MINDSTORMS Robot Inventor (51515) під час оновлення через застосунок SPIKE Legacy, чому застосунок після цього постійно вимагав оновлення, і як це виправити за 10 хвилин.

Усе описане перевірено на одному хабі: апаратна версія Version_E, Mac на Apple Silicon, macOS 26.6.2, SPIKE Legacy 2.0.10, зв'язок по Bluetooth. На іншому обладнанні результат може відрізнятися.

## Коротко

1. Оновлення через SPIKE Legacy показало помилку, але нову прошивку на хаб записало.
2. Після цього застосунок при кожному підключенні показував вікно «Update Hub» і не пускав далі.
3. Причина: відповідь хаба про свою версію мала рівно 1023 символи. Відповідь такої довжини хаб надсилає по Bluetooth без символу кінця повідомлення, застосунок не може її прочитати й вважає, що хаб потребує оновлення.
4. Виправлення: скоротити один службовий список на хабі. Після цього відповідь має 519 символів, і застосунок підключається нормально.

Це помилка програмного забезпечення LEGO, а не дій користувача. Повторне натискання UPDATE її, найімовірніше, не виправляє, бо список лишається тим самим.

## Що ми бачили

Хаб до оновлення працював на прошивці MINDSTORMS (runtime 3.2.36).

| Час | Подія |
| --- | --- |
| 01:02 | SPIKE Legacy підключився до хаба й почав оновлення по Bluetooth |
| 01:11 | хаб зник зі зв'язку: перезавантаження для запису прошивки |
| 01:16 | хаб знову з'явився |
| 01:17 | застосунок показав «An error occurred while updating the Hub OS. Please reconnect the Hub and try again.» |

Після цього ми прочитали стан хаба напряму, без застосунку:

- прошивка `v1.3.00.0000-e8c274a`, runtime `4.0.0.7`. Це версії, які встановлює SPIKE Legacy 2.0.10, тобто оновлення відбулося;
- усі 8 збережених програм лишилися на хабі.

Попри це, при кожному підключенні застосунок показував вікно «Update Hub: The Hub OS needs to be updated» з єдиною кнопкою UPDATE.

## Причина

Після підключення застосунок надсилає хабу запит `get_hub_info`, щоб дізнатися версії. Ми надіслали хабу той самий запит і записали відповідь.

- **Відповідь приходила пошкодженою.** Вона мала рівно 1023 символи й не закінчувалася символом кінця повідомлення. До неї приклеювалося наступне повідомлення хаба, тому розібрати її як дані було неможливо.
- **Межа — 1022 символи.** Ми перевірили окремо: після повідомлення на 1000, 1014 і 1022 символи хаб надсилає символ кінця, після повідомлення на 1023 символи не надсилає. Відповідь на 1032 символи прийшла обрізаною.
- **Застосунок трактує це як «хаб не відповів».** У його журналі з'являється `Could not get firmware info`. За кодом застосунку в такому разі він вимагає оновлення.
- **Довжину відповіді визначав службовий список.** У відповідь входить вміст файла `.extra_files_hash` на хабі. Там було 86 записів про звукові файли MINDSTORMS: 773 символи з 1023.

Із 85 записами відповідь була б коротшою за межу. Тобто помилку спричинило точне число файлів, які лишилися від MINDSTORMS.

## Що не встановлено

- **Чому саме оновлення показало помилку о 01:17.** У журналі застосунку одразу після перезавантаження хаба стоїть той самий запис `Could not get firmware info`, а за ним `Firmware update failed`. Це узгоджується з описаною причиною, але окремо ми цього не доводили.
- **Чому список лишився старим.** Припущення: оновлення обірвалося до кроку, на якому застосунок переписує цей список.
- **Чи проявляється це через USB-кабель.** Ми перевіряли лише Bluetooth.

## Виправлення на Mac

**Що потрібно:** Mac, увімкнений Bluetooth, Python 3 і папка з інструментом `hub` (цей репозиторій або архів). Кабель не потрібен. Якщо Python 3 немає, виконайте `xcode-select --install`.

Хаб має бути у списку Bluetooth-пристроїв Mac як «LEGO Hub …». Якщо SPIKE Legacy уже підключався до нього з цього Mac, він там є.

### Підготовка (один раз, 2 хвилини)

Відкрийте Термінал у папці з інструментом і виконайте:

```sh
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
```

### Кроки (5–10 хвилин)

Кожна команда виконується 10–30 секунд, це нормально. Виконуйте їх по одній.

1. **Закрийте SPIKE Legacy через Cmd-Q.** Закрити вікно недостатньо: застосунок лишається у фоні й тримає зв'язок із хабом. Застосунок LEGO на планшеті теж закрийте.
2. **Увімкніть хаб** коротким натисканням центральної кнопки.
3. **Перевірте, що оновлення відбулося:**
   ```sh
   ./hub status
   ```
   У рядку `Runtime` має бути `4.0.0`. Якщо там `3.2.36`, прошивка не оновилася, і цей документ вам не підходить.
4. **Перевірте, що причина та сама:**
   ```sh
   ./hub inforeply
   ```
   Очікуваний результат: `Відповідь пошкоджена`. Якщо написано `Відповідь правильна`, причина інша, далі не продовжуйте.
5. **Збережіть копію списку:**
   ```sh
   ./hub exec "print(open('.extra_files_hash').read())" > extra_files_hash.orig
   ```
6. **Скоротіть список:**
   ```sh
   ./hub run fix_extra_files_hash.py
   ```
   Очікуваний результат: `Було записів: 86, стало: 30`. Перше число у вас може бути іншим.
7. **Перевірте ще раз:**
   ```sh
   ./hub inforeply
   ```
   Тепер має бути `Відповідь правильна`.
8. **Відкрийте SPIKE Legacy і підключіть хаб.** Вікно «Update Hub» більше не з'являється.

Скрипт змінює лише службовий список. Звукові файли, програми й прошивка лишаються як були. SPIKE Legacy 2.0.10 ці записи, судячи з його коду, не використовує: список додаткових файлів там не заданий.

### Якщо результат інший

| Що бачите | Що це означає | Що робити |
| --- | --- | --- |
| `Спершу повністю закрийте SPIKE Legacy` | застосунок ще працює у фоні | Cmd-Q у застосунку, повторити команду |
| `Хаб не відповідає` | хаб вимкнений або далеко | увімкнути хаб, повторити |
| `Mac не має спареного хаба LEGO` | хаба немає у списку Bluetooth | Налаштування → Bluetooth, натиснути кнопку Bluetooth на хабі й підключити «LEGO Hub …» |
| `Не вдалося відкрити канал RFCOMM` | до хаба підключена інша програма | закрити всі застосунки LEGO, зачекати 15 секунд |
| після кроку 8 знову «Update Hub» | причина не лише в довжині відповіді | не натискати UPDATE, перевірити журнал (див. «Докази») |

Хаб сам вимикається через кілька хвилин бездіяльності. Якщо команда каже, що хаб не відповідає, просто ввімкніть його знову.

## Як повернути список

Повертати його потрібно лише перед поверненням на прошивку MINDSTORMS. Цю команду ми не перевіряли:

```sh
./hub exec "f=open('.extra_files_hash','w'); f.write('$(tr -d '\r\n' < extra_files_hash.orig)'); f.close()"
```

## Без Mac або без цього інструмента

Цей шлях ми не перевіряли. Хаб має консоль MicroPython на послідовному порту: через USB-кабель із передачею даних або через Bluetooth. Підключіться будь-яким терміналом на швидкості 115200, зачекайте кілька секунд, натисніть Ctrl-C один раз і введіть:

```python
p = open('.extra_files_hash').read().strip().split(';')
print(len(p))
f = open('.extra_files_hash', 'w'); f.write(';'.join(p[:30])); f.close()
```

Потім натисніть Ctrl-D: хаб перезапустить свою програму. На macOS 26 Bluetooth-порт `/dev/cu.LEGOHub…` у нас не передавав дані, тому там потрібен інструмент `hub` або USB-кабель.

## Докази

Журнал SPIKE Legacy лежить тут:

```
~/Library/Containers/com.lego.education.spike/Data/Library/Application Support/SPIKE/logs/spike.log
```

Записи під час оновлення (час UTC, місцевий на годину більший):

```
00:16:59  Could not get firmware info after 8000ms
00:17:09  Could not get firmware info after 10000ms
00:17:18  connect caught exception:, Unable to connect
00:17:23  Firmware update failed Could not readUntil: Timeout waiting 10 secs for 'OK'
```

Ті самі записи `Could not get firmware info` з'являлися при кожній наступній спробі підключення, поки список не скоротили.

Вимірювання на хабі:

| Перевірка | До виправлення | Після |
| --- | --- | --- |
| записів у `.extra_files_hash` | 86 | 30 |
| довжина відповіді `get_hub_info` | 1023 символи, без символу кінця | 519 символів |
| правильних відповідей із 5 запитів | 0 | 5 |
| SPIKE Legacy | вимагає Update Hub | підключається, програма з блоків запускається |

Проміжна спроба додати один запис замість видалення (87 записів, відповідь 1032 символи) не допомогла: відповідь прийшла обрізаною.

## Що не перевірено

- Інші хаби, Windows, Linux, планшети й старіші версії macOS.
- Підключення через USB-кабель.
- Спарювання хаба з Mac «з нуля»: наш хаб уже був у списку Bluetooth.
- Чи запускаються старі програми MINDSTORMS на новій прошивці.
- Команди `./hub inforeply` і поточна версія `fix_extra_files_hash.py` на справжньому хабі. Їхня логіка перевірена на записаних відповідях, а попередня версія скрипта спрацювала на хабі.

Більше про інші проблеми з підключенням: [TROUBLESHOOTING.md](TROUBLESHOOTING.md).
